# 全屏修复（FullscreenFix）— 简洁版发布帖

> 适用：SPT 5.0 BE（1.3.0.1.48558）· BepInEx 6 IL2CPP

---

**设置里选了「全屏」，下次启动又变「无边框」？**

先说个反直觉的事实：**你的设置从来没被改回去。**

`Graphics.ini` 里 `FullScreenMode` 是 `0`，注册表 `Screenmanager Fullscreen mode` 也是 `0`，两个都是「全屏」。游戏每次启动确实都在申请独占全屏。

真正发生的事在 `Player.log` 里：

```
dxgi: swapchain SetFullscreenState failed (887a0022).
Failed to apply requested ExclusiveFullScreen resolution (1680x1050)...will try again
Unable to apply requested ExclusiveFullScreen resolution again (1680x1050)...reverting to current display resolution: 2880x1800
Failed to change display to ExclusiveFullscreen...reverting to FullscreenWindow
```

翻译：Unity 想进独占全屏 → 失败（`0x887A0022`）→ 以为分辨率不匹配，去切显示模式 → 切模式也被拒 → 放弃，回退成无边框。

**所以你改 ini、改注册表都没用 —— 那些值本来就是对的。**

---

## 修的是什么

这台机器上（可能你的也是）**普通进程切不了桌面显示模式**：

- `SetFullscreenState(TRUE, …)` 恒失败
- `ChangeDisplaySettingsEx` 连「什么都不改」的空操作都返回 `ERROR_ACCESS_DENIED`

于是独占全屏只剩一条路：**请求分辨率正好等于桌面当前模式**，这样 Unity 不需要切模式，可以直接以独占全屏创建交换链。

但游戏存的分辨率和桌面不一致（比如存 1680x1050、桌面 2880x1800），所以每次都撞墙。

**插件做的核心一件事：让两者一致。**

它在你退出游戏后，把 PlayerPrefs 里的分辨率改成显示器原生值。下次启动时引擎请求的分辨率就正好等于桌面模式 → 不需要切模式 → 独占全屏一次成立。

> 为什么必须在「上一次退出时」改：Unity 引擎在 `Player.log` 第 18 行就发起那次全屏请求，那时候 BepInEx 连加载都还没开始，任何补丁都拦不住。

其余是配套：五处 Harmony 补丁（只观测，默认不改写你的请求）+ 启动自检 + 运行时模式记录，日志里会明确告诉你结果：

```
[全屏修复] 游戏请求 SetResolution(1680x1050, ExclusiveFullScreen) —— 原样放行
[全屏修复] ... → 实际显示模式 = ExclusiveFullScreen ✔ 真·独占全屏
```

看到 ✔ 就是成了。

---

## 装法

1. 关游戏
2. `BepInEx\plugins\FullscreenFix\FullscreenFix.dll`
3. 启动一次 → 日志说要「下次启动才生效」的话，**再启动一次**
4. 看日志里的 `实际显示模式`

不需要 ConfigurationManager，不改 `Graphics.ini`，不动 exe 属性。只写 HKCU，不碰游戏目录任何文件。

---

## 一个必须说清的取舍

默认配置会把**渲染分辨率顶到显示器原生值**。如果你原本是刻意用低分辨率换帧数，那：

- **开着**（默认）→ 独占全屏成立，但像素量可能涨 2～3 倍
- **关掉 `PinNativeResolutionInPlayerPrefs` + `ForceNativeResolution`** → 分辨率随你，但**独占全屏就不成立了**，画面是无边框

这是个二选一。前提是这台机器切不了显示模式 —— 能切的机器根本不需要这插件。

**好消息**：如果你的低分辨率和屏幕同宽高比（16:10 屏用 16:10），无边框全屏会缩放铺满、没有黑边，视觉上和全屏几乎没差别。

---

## 什么时候你不需要它

- 日志里**没有** `SetFullscreenState failed` / `reverting to FullscreenWindow` → 你的机器独占全屏本来就正常，别装
- 你的全屏问题是被 overlay 干扰的（RTSS / Afterburner / GameViewer / UU）→ 先退出那些试试，比装插件简单

---

## 已知限制

1. **只在作者本机验证过**（MECHREVO WUJIE 14 / AMD 780M / Win11 26300 / 2880x1800@120 / 150% DPI）。别的硬件上失败原因可能完全不同
2. **「禁用全屏优化」那个勾别勾** —— 本机实测勾上会直接启动失败。装了插件也不需要它了
3. `KeepStoredExclusive` 只让界面显示「全屏」，不代表渲染真是独占全屏。真相看日志那行 `实际显示模式`
4. 卸载后进游戏设置手动重选一次分辨率（PlayerPrefs 里可能还留着被钉的值）

---

## 还是 `✘` 的话，按顺序查

1. 日志里搜「已把 PlayerPrefs」—— 有没有 4 个键被改？改完**重启游戏**了吗？
2. 日志第一段的「当前分辨率」和「桌面分辨率」是否相等？
3. 自检里有没有 `GameViewer Virtual Display Adapter` / `Sunshine` / `Parsec`？有就退出对应软件
4. 退出 RTSS / MSI Afterburner
5. 关 GameDVR（设置 → 游戏 → 游戏栏）
6. 重装显卡驱动，勾「恢复出厂设置」
7. 都不行 → 打开 `Fix/ForceBorderless`，接受无边框（至少画面是干净铺满的）

## 反馈请附这两段

1. `BepInEx\LogOutput.log` 里所有 `[全屏修复]` 开头的行
2. `Player.log` 里搜 `Fullscreen` 的结果

有这两段基本能定位卡在哪一步。

**技术备注**

- 判定「请求分辨率是否等于桌面模式」用 `Display.main.systemWidth/systemHeight`（`Screen.currentResolution` 在无边框下返回窗口尺寸，会误判）
- `FullScreenModeConverter.ToInt`、`SwitchDisplay*`、`ChangeMode`、`ApplyDisplaySettings` 全部 `CallerCount(0)` + `InlinedInto`，**打补丁无效**；能用的注入点只有 `EFTDisplayHelper.SetResolution` 的两个重载
- EFT 类型一律字符串反射解析（Il2CppInterop 生成的类型编译期不可见，直接引用会 CS0122），类型改名时能优雅降级而不是崩溃
- Hook 走 `Il2CppDetourMethodPatcher`，支持 `ref` 参数（含装箱 struct byref）
