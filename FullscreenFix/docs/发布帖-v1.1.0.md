# 全屏修复（FullscreenFix）v1.1.0 — 发布帖

> 适用：逃离塔科夫 SPT 5.0 BE（Client 1.3.0.1.48558 / SPT 5.0.0-048e0aa）/ BepInEx 6 IL2CPP

---

## 一句话

**设置里选了「全屏」，每次启动却自动变回「无边框」？不是你的设置被改回去了，是游戏想进全屏但被系统挡了回来。这个插件把那条被挡住的路绕开。**

---

## 你大概遇到过这些

- 设置 → 屏幕模式选「全屏」，退出游戏，下次进来又变成「无边框」
- 反反复复改，`Graphics.ini` 里看着是 `FullScreenMode: 0`（= 全屏），但画面就是无边框
- 去 exe 属性里勾「禁用全屏优化」，结果游戏**根本启动不了**
- 折腾 `Graphics.ini`、改 `PlayerPrefs` 注册表，改完当次有效，下次又回去了

如果你全中，这篇就是给你写的。

---

## 真正发生了什么（这才是重点）

**你的设置从来没被改回去。**

打开这两个地方看，值一直是对的：

| 位置 | 键 | 值 | 含义 |
|---|---|---|---|
| `SPT_Runtime\user\sptSettings\Graphics.ini` | `DisplaySettings.FullScreenMode` | `0` | 全屏（独占） |
| `HKCU\Software\Battlestate Games\EscapeFromTarkov` | `Screenmanager Fullscreen mode_h3630240806` | `0` | 全屏（独占） |

Unity 的枚举是 `0 = ExclusiveFullScreen`，两个地方存的都是 0。**游戏每次启动确实都在申请独占全屏。**

那为什么画面是无边框？去 `%LOCALAPPDATA%Low\Battlestate Games\EscapeFromTarkov\Player.log` 里搜 `Fullscreen`，你会看到这样一串：

```
dxgi: swapchain SetFullscreenState failed (887a0022).
Failed to apply requested ExclusiveFullScreen resolution (1680x1050)...will try again
Unable to apply requested ExclusiveFullScreen resolution again (1680x1050)...reverting to current display resolution: 2880x1800
Failed to change display to ExclusiveFullscreen...reverting to FullscreenWindow
```

翻译一下：

1. Unity 调 `IDXGISwapChain::SetFullscreenState(TRUE)` 想进独占全屏 → **失败**，返回 `0x887A0022`
2. 它以为是自己分辨率（1680x1050）和桌面（2880x1800）不一致，决定**切换显示模式**再试
3. 模式切换也失败（`ChangeDisplaySettingsEx` 被系统拒绝）
4. Unity 放弃，回退成 `FullscreenWindow` —— **这就是你看到的「无边框」**

`0x887A0022` = `DXGI_ERROR_NOT_CURRENTLY_AVAILABLE`。

所以：**不是配置问题，是运行时建立独占全屏失败。** 改 ini、改注册表都没用 —— 那些值本来就是对的。

---

## 为什么会失败

我用不依赖游戏的独立 DXGI 探针在本机完整测过（隐藏窗口 / 可见窗口 / 抢前台 / flip 模型 / bitblt 模型 / 指定输出 / 原生分辨率 / 创建时即全屏，全部组合），结论是：

- `SetFullscreenState(TRUE, …)` 在本机**恒定失败**
- `ChangeDisplaySettingsEx` 连「什么都不改」的空操作都返回 `ERROR_ACCESS_DENIED`

也就是说，**这台机器上普通进程无法切换桌面显示模式**。

于是独占全屏只剩下**一条**能走通的路：

> 请求的分辨率 **正好等于** 桌面当前模式 → Unity 不需要切模式 → 直接以独占全屏创建交换链 → 成功。

而游戏存档里写的是 `1680x1050`，桌面是 `2880x1800` —— 不一致，所以每次都要切模式，每次都被拒。

---

## 插件做了什么

四个字：**让它一致。**

### 1. 把 PlayerPrefs 里的分辨率钉成显示器原生值

这是唯一真正关键的一步。

Unity 引擎在 `Player.log` 第 18 行就发起了那次全屏请求 —— 那时候 **BepInEx 和任何插件都还没加载**。所以任何 Harmony 补丁都救不了那一次，只能在**上一次退出时**就把值改好。

插件启动时直接改 `HKCU\Software\Battlestate Games\EscapeFromTarkov` 下的这几个键：

```
Screenmanager Resolution Width_h182942802
Screenmanager Resolution Height_h2627697771
Screenmanager Resolution Window Width_h2524650974
Screenmanager Resolution Window Height_h1684712807
```

用前缀匹配而不是写死键名（Unity 的 PlayerPrefs 键名带名字哈希，换版本会变）。**只写 HKCU，不碰游戏目录任何文件。**

改完**下次启动**生效 —— 那时引擎请求的分辨率就等于桌面模式，不需要切模式，独占全屏一次成立。

### 2. 五处 Harmony 补丁（观测为主，改写为辅）

反编译确认了整个 `Assembly-CSharp` 里对 `Screen.SetResolution` 的调用**只出现在** `EFT.Settings.Graphics.EFTDisplayHelper` 的两个静态重载里，所以注入点很明确：

| 注入点 | 作用 |
|---|---|
| `EFTDisplayHelper.SetResolution(int,int,FullScreenMode)` | 主入口：记录每次请求 + 返回后报告**实际**显示模式 |
| `EFTDisplayHelper.SetResolution(int,int)` | 同上（两参重载） |
| `UnityEngine.Screen.fullScreenMode` setter | 捕获游戏其它走属性赋值的路径 |
| `GraphicsSettingsGroup.StoreDisplaySettings(EftDisplaySettings)` | 让保存值/界面继续显示「全屏」 |
| `GraphicsSettingsGroup.GetStoredDisplaySettings(ref EftDisplaySettings)` | 同上（读取时） |

默认**不改写你的任何请求**，只观测。日志里会明确告诉你结果：

```
[全屏修复] 游戏请求 SetResolution(1680x1050, ExclusiveFullScreen) —— 原样放行
[全屏修复] 游戏请求 SetResolution(...) → 实际显示模式 = ExclusiveFullScreen ✔ 真·独占全屏
```

看到 ✔ 就是真的成功了，看到 ✘ 就说明还没成。

### 3. 启动自检

日志里会列出：当前分辨率、桌面分辨率、`Screen.fullScreenMode` 实际值、`Screen.fullScreen`、显示器枚举（会**特意标出**虚拟显示适配器，比如网易 UU / GameViewer 的 IDD 虚拟屏 —— 这类东西是 DXGI 独占全屏的常见干扰源）。

### 4. 运行时观察者

每 0.5 秒采样一次显示模式，变化时写进日志：

```
[全屏修复] 显示模式变化：ExclusiveFullScreen -> FullScreenWindow  (第 3 次采样, 3.0s)
```

这样你能精确看到「第几秒被谁退回去了」，排查很有用。

## 安装

1. **关掉游戏**
2. 把 `BepInEx\plugins\FullscreenFix\FullscreenFix.dll` 放到游戏的 `BepInEx\plugins\FullscreenFix\`
3. 启动游戏一次 —— 这**第一次**还需要你看日志确认插件加载了
4. 如果日志显示「已把 PlayerPrefs 里的分辨率改成原生 …，**下次启动才生效**」，就**再启动一次**
5. 看日志里的 `实际显示模式 = …`

不需要 `ConfigurationManager`，不需要改 `Graphics.ini`，不需要动 exe 属性。

> 前置：游戏必须已经装好 BepInEx 6（IL2CPP）。SPT 5.0 BE 一般自带。

---

## 配置（`BepInEx\config\dsh.FullscreenFix.cfg`）

| 项 | 默认 | 说明 |
|---|---|---|
| `General/Enabled` | `true` | 总开关 |
| `Fix/PinNativeResolutionInPlayerPrefs` | **`true`** | **核心项**：把 PlayerPrefs 分辨率钉成原生。关掉就不会再改你的分辨率 |
| `Fix/ForceNativeResolution` | `true` | 强制把运行时请求的分辨率改成原生（不改屏幕模式） |
| `Fix/ForceBorderless` | `false` | 把全屏请求强行改写成无边框。**这是退路，不是解法** |
| `Fix/KeepStoredExclusive` | `true` | 让保存值/界面继续显示「全屏」，避免你下次打开设置又看到「无边框」 |
| `Debug/Verbose` | `true` | 详细日志，排查时保持开启 |

### 关于那个「代价」

`PinNativeResolutionInPlayerPrefs` 和 `ForceNativeResolution` 默认开着，意味着**渲染分辨率会被顶到显示器原生值**。

如果你原本是刻意用低分辨率换帧数（很多人这么干），那么：

- **关掉这两项** → 分辨率保持你选的，但**独占全屏就不成立了**，画面会是无边框
- **开着** → 独占全屏成立，但渲染像素可能是个大数字（我本机是 1680x1050 → 2880x1800，约 **2.9 倍**像素）

这是个二选一，取决于你更在意「设置里显示全屏」还是「帧数」。**别指望两者兼得** —— 前提是这台机器切不了显示模式。

好消息是：如果你选的是一个和桌面同宽高比的低分辨率（比如 16:10 的屏幕用 16:10 的分辨率），无边框全屏会把画面**缩放铺满**，没有黑边，视觉上和全屏几乎一样。

## 如果日志显示 `✘ 无边框`

按这个顺序查：

1. **确认 `PlayerPrefs` 那边真的改了** —— 日志里搜「已把 PlayerPrefs」，要看到 4 个键被改；改完必须**重启游戏**才生效
2. **确认请求分辨率 == 桌面分辨率** —— 日志第一段会打印两者，不一致就还是走不通
3. **看自检里的虚拟显示适配器** —— 有 `GameViewer Virtual Display Adapter` / `Sunshine` / `Parsec` 之类，试着退出对应软件（网易 UU、GameViewer）后重开游戏
4. **关掉 overlays** —— RTSS / MSI Afterburner / 各种游戏内覆盖，它们会 hook DXGI
5. **关 GameDVR** —— 设置 → 游戏 → 游戏栏，关掉「录制」
6. **重装显卡驱动**，安装时勾「恢复出厂设置」
7. 以上都试过还不行 → 打开 `Fix/ForceBorderless`，接受无边框（至少画面是干净的铺满，不会闪）

## 已知限制（请务必读完再决定装不装）

**1. 这个插件治的是「模式切换被拒」这一类失败，不是万能的。**

如果你的机器上独占全屏本来就正常（大多数人其实是正常的），你**不需要这个插件**。它的存在前提是：日志里出现 `SetFullscreenState failed` + `reverting to FullscreenWindow`。

**2. 只在作者本机验证过。**

作者的机器：MECHREVO WUJIE 14 / AMD Radeon 780M / Win11 26300 / 内屏 2880x1800@120 / 150% DPI。别的硬件组合上，失败原因可能完全不同，那时的正确解法也不同（比如纯软件层面的覆盖冲突，退出 RTSS 就好了）。

**3. `KeepStoredExclusive` 只影响「保存值 / 界面显示」，不代表渲染真的是独占全屏。**

想知道真相，只看日志里那行 `实际显示模式 = …`。

**4. 「禁用全屏优化」那个勾，不要勾。**

它和本插件试图绕开的是同一套系统机制。本机实测勾上会直接启动失败。装了插件之后你也不需要再去勾它了。

**5. 卸载后请手动复位分辨率。**

删掉 dll 之后，PlayerPrefs 里可能还留着被钉成原生的分辨率。进游戏设置里重新选一次你想要的就行。

---

## 卸载

1. 关游戏
2. 删 `BepInEx\plugins\FullscreenFix\`
3. 删 `BepInEx\config\dsh.FullscreenFix.cfg`
4. 进游戏设置，重新选一次分辨率 + 屏幕模式

它没有往游戏目录写过任何东西（只写了 HKCU 的 PlayerPrefs），所以卸载很干净。

## 技术备注（给想深究的人）

- 判定「请求分辨率是否等于桌面模式」用的是 `Display.main.systemWidth/systemHeight`，不是 `Screen.currentResolution` —— 后者在无边框下会返回窗口尺寸，会误判
- `FullScreenModeConverter.ToInt / ToFullScreenMode` 是 `CallerCount(0)` + 已内联，**打了没用**；`SwitchDisplay*` / `ChangeMode` / `ApplyDisplaySettings` 系列同样带 `InlinedInto`，所以能用的注入点只有上面那两个 `SetResolution` 重载
- 所有 EFT 类型都用字符串 + 反射解析（`AccessTools.TypeByName`），因为 Il2CppInterop 生成的类型在编译期不可见（CS0122），反射能在类型改名时优雅降级而不是崩溃
- Hook 用的是 `Il2CppDetourMethodPatcher`，支持 `ref` 参数（含装箱 struct byref）
