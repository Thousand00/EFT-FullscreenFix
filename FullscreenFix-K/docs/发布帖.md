# 【SPT 5.0 BE / 客户端插件】全屏修复 K1 —— 治一治「每次启动都变无边框」

> 状态：**v0.3.0 公测中**，欢迎帮忙跑一次并把日志发回来。
> 仓库：https://github.com/Thousand00/FullscreenFix-K

---

## 先说结论

SPT 5.0 BE 启动时进不了独占全屏、被 Unity 强制回退成无边框，**不是你的设置没保存，也不是 SPT 的锅**。

`Graphics.ini` 里 `FullScreenMode` 一直是 `0`（=全屏），文件从头到尾没被改过。
真正发生的事在 `Player.log` 里：

```
dxgi: swapchain SetFullscreenState failed (887a0022).
Failed to apply requested ExclusiveFullScreen resolution (1680x1050)...will try again
Unable to apply requested ExclusiveFullScreen resolution again (1680x1050)...reverting to current display resolution: 2880x1800
Failed to change display to ExclusiveFullscreen...reverting to FullscreenWindow
```

翻译成人话：**游戏确实按你的设置去申请独占全屏了，但 DXGI 那一下没成功，Unity 就自己退回无边框，而且不回写设置**。
所以你在主菜单看到的是「无边框」，文件里却还是「全屏」——两边对不上，看起来就像设置失灵。

---

## 为什么以前的思路（改设置 / 打补丁）都没用

我把这三串字符串在所有相关二进制里搜了一遍：

| 文件 | 命中 |
| --- | --- |
| `UnityPlayer.dll` | 各 1 次 |
| `Assembly-CSharp.dll` | 0 |
| `GameAssembly.dll` | 0 |
| `global-metadata.dat` | 0 |

结论很干脆：**「切独占全屏失败 → 回退无边框」是 Unity 原生 C++ 里的逻辑，不是托管代码**。
BepInEx 的 Harmony 只能改托管方法，碰不到它。任何“拦截回退”“强制写设置”的插件，方向从一开始就是错的。

---

## 那到底能不能进独占全屏？能。

决定性的一步：**进游戏之后手动切一次「全屏」，就成功了**。

同一台机器、同一个分辨率、同一个 API，**早 10 秒失败，晚 10 秒成功**。
而且切成功之后，`Player.log` 从第 426 行一直到文件末尾（38 万多行）**再没有任何一次 dxgi 失败**。

所以这不是硬件不支持，是**纯粹的时机问题**：游戏启动那一小段时间里，显示栈还没准备好接受独占全屏请求。
Unity 自己也知道要等——它内部有 `ApplyDelay = 300ms`、`AwaitScreenReady()`、`DisplayOffCoroutine` 这些东西，
但显然对某些机器来说 300ms 不够。

顺带一个佐证：Unity 自己的日志里是 `will try again` → `again` → `reverting`，**它也在重试，只是重试完就放弃了**。

---

## 这个插件做什么

一句话：**等时机真的到了，再替你把那次请求重新发一遍，然后如实告诉你成没成。**

1. 挂 `EFT.UI.MenuScreen.Show` 的**全部重载**，主菜单一出现就拿到确切信号
   （等不到就按超时退化，默认 45 秒）
2. 信号到 → 等一小会儿 → 调 `EFTDisplayHelper.SetResolution(w, h, ExclusiveFullScreen)` 重新申请
3. **验证**：要求独占全屏状态**连续保持 3 秒**才算成功
   —— 这一步是踩过坑的。请求发出去的瞬间，Unity 会先把「期望模式」置上，
   等 swapchain 真的失败才回退。所以只看一眼会读到**回退前的假象**，误判成成功。
4. 失败 → 指数退避重试（4→6→9→13.5→20→30→45 秒封顶），默认最多 10 次，覆盖启动后 2～3 分钟
5. 热键 **F9** 随时手动再来一次

### 它不做什么

- ❌ 不改 `Graphics.ini`
- ❌ 不改 `PlayerPrefs` / 注册表
- ❌ 不改存档
- ❌ **不会**把「全屏」偷偷改成「无边框」让设置看起来一致
- ❌ 失败时不会假装成功

## 安装

1. 下载 `K1FullscreenFix.dll` 和 `K1FullscreenFix.pdb`（**两个都要**，pdb 是给报错堆栈抓行号用的）
2. 放进：

```
<游戏目录>\BepInEx\plugins\K1FullscreenFix\
```

例如 `D:\EFT-5.0 BE\BepInEx\plugins\K1FullscreenFix\K1FullscreenFix.dll`

3. 启动游戏，首次运行会生成 `BepInEx\config\dsh.k1.fullscreen.cfg`

> 需要 BepInEx 5 / IL2CPP 环境（SPT 5.0 BE 自带）。

---

## 日志（排查只看这一个文件）

```
<游戏目录>\BepInEx\K1Logs\K1FullscreenFix.log
```

- 上一次的会改名成 `K1FullscreenFix.prev.log`
- 每行带毫秒时间戳
- 高频细节只进这个文件，**不会刷爆 `LogOutput.log`**

### 成功长这样

```
[K1] 请求 1680x1050 独占全屏
[K1] 观察：FullScreenWindow → ExclusiveFullScreen
[K1] ✔ 第 1 次尝试成功：已连续保持 3.0s
```

关键判据不是「看到 ✔」，而是 **✔ 之后日志里不再冒出 Unity 的 `reverting to FullscreenWindow`**。

### 失败长这样

```
[K1] ✘ 第 1 次尝试失败：观察 6s 后是 FullScreenWindow
[K1] 第 2 次：等 6s 后重试
```

如果是这种情况，**把整个 `K1FullscreenFix.log` 发给我**，里面记了模式、分辨率、时间点，够定位。

## 配置

`BepInEx\config\dsh.k1.fullscreen.cfg`

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `General/Enabled` | `true` | 总开关 |
| `General/Verbose` | `true` | 详细日志 |
| `Retry/AutoRetryOnStartup` | `true` | 启动自动重试 |
| `Retry/MaxAttempts` | `10` | 最多试几次 |
| `Retry/InitialDelaySeconds` | `1` | 主菜单出现后等多久再发请求 |
| `Retry/StableSeconds` | `3` | 连续保持多久才算真成功 |
| `Retry/BackoffSeconds` | `4` | 首次失败后的等待 |
| `Retry/BackoffGrowth` | `1.5` | 退避倍数 |
| `Retry/MaxBackoffSeconds` | `45` | 退避上限 |
| `Retry/Resolution` | `Current` | `Current` 用当前分辨率；`Native` 用屏幕物理分辨率 |
| `Retry/ManualHotkeyEnabled` | `true` | F9 热键 |
| `Retry/ManualHotkey` | `F9` | 改成别的键也可以 |

### 调参提示

- **还是进不去**：把 `MaxAttempts` 加大到 `20`、`MaxBackoffSeconds` 加到 `90`，让它多盯一会儿
- **分辨率不对**：`Retry/Resolution` 改 `Native`
- **不想它自己动**：`AutoRetryOnStartup = false`，只留 F9 手动

## 已知情况

- **v0.3.0 还没实测成功过**。前两版失败的原因都已定位（详见仓库 README 的版本历史），这版是修完刚编出来的。
- 如果你机器上「启动后手动切全屏」也切不成功，那这插件大概率也帮不上——那是另一个问题
  （建议查：显卡驱动的显示模式、多显示器/虚拟显示适配器、远程桌面类软件）。
- 只测过 AMD Radeon 780M + Windows 11 + 1680x1050 → 2880x1800 这一套，**其他硬件欢迎反馈**。
